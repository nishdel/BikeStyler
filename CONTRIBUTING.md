# Contributing

Use Node.js 24 and the lockfile. Keep changes focused, preserve portable-project validation and test visible behaviour rather than mirroring implementation. Run type checks, unit checks and build; run relevant browser checks for editing, persistence or rendering changes. See [development](docs/DEVELOPMENT.md) and [testing](docs/TESTING.md).

For a bug, give browser/version, steps, expected and actual result. Prefer the bundled sample. Do not attach private photographs, portable projects, traces, account details or tokens without reviewing them. For visual changes, include a genuine before/after screenshot and explain image provenance.

Product additions need source URLs and explicit uncertainty. Asset contributions need permission for inclusion, origin labels and transparent boundaries; generated references must stay labelled. Do not infer fit from a preview.

Update canonical documentation when behaviour or evidence changes. Keep private integration configuration out of commits. A code licence has not yet been selected; discuss contribution and reuse terms before substantial external code contributions. See [licensing](docs/LICENSING.md).
